## 사용하면 유용한 다이어그램들
### Class Diagram
- 정적 다이어그램
- 클래스들과 그들 간의 관계를 시각적으로 표현
- 소프트웨어의 객체 지향적인 구조를 이해하는 데 매우 유용
- 클래스의 이름, 속성, 메서드, 클래스 간의 상속, 연관성 등을 보여줍니다. 
- 또한 클래스 다이어그램은 객체의 생성과 제거, 메시지의 흐름, 클래스의 상호작용을 표현할 수도 있습니다.
![|575](https://i.imgur.com/b2ZZxRl.png)

### Package Diagram
- 정적 다이어그램
- 소프트웨어 시스템의 구성 요소들을 논리적으로 그룹화하여 표현
- 패키지는 클래스, 인터페이스, 컴포넌트 등의 집합이며, 이들 간의 종속성과 계층 구조를 나타냅니다
- 패키지 다이어그램은 **시스템의 모듈화와 재사용성을 이해**하는 데 도움을 줌
- 또한 패키지 다이어그램은 소프트웨어의 **논리적인 구조를 시각적으로 표현**함으로써 개발자들 간의 의사 소통을 원활하게 만듭니다.
![|875](https://i.imgur.com/AmtGKtC.png)

### Sequence Diagram
- 동적 다이어그램
- **시스템의 객체들 간의 상호작용과 메시지 흐름을 시간순으로 표현**
- 객체 간의 메시지 교환과 호출 순서를 시각적으로 보여줌
- 시스템의 동작을 이해하고 디버깅하는 데 유용하며, 특정 상황에서의 객체 간의 상호작용을 시각화할 수 있습니다.
![|775](https://i.imgur.com/jQsQ2eO.png)
### State Diagram
- 동적 다이어그램
- 시스템의 객체의 상태와 상태 전이를 표현하는 데 사용
- 객체의 생명주기와 가능한 상태들을 보여주며, 이벤트에 의한 상태 전이를 표현합니다
- 객체의 동작과 제약 조건을 이해하고, 객체의 상태 전이를 시각화하여 설계 결정을 내리는 데 도움을 줍니다.
![|600](https://i.imgur.com/3gVge5V.png)

### Batch Diagram
- 물리적 다이어그램
- 시스템의 구성 요소들이 물리적으로 배치되는 방식을 보여줌
- 서버, 네트워크 장치, 컴퓨터 등과 같은 물리적인 요소들의 위치와 연결 상태를 표현
- 시스템의 아키텍처를 이해하고 구성 요소들 간의 상호작용을 파악하는 데 도움을 줌
![|875](https://i.imgur.com/c0bYc3B.png)


### Component Diagram
- 소프트웨어 시스템의 구성 요소들과 그들 간의 인터페이스를 표현
-  소프트웨어의 모듈화와 컴포넌트 간의 종속성을 보여줌
- 시스템의 구성 요소들을 논리적으로 그룹화하여 표현하며, 소프트웨어의 재사용성과 유지보수성을 개선하는 데 도움을 줍니다.
![|950](https://i.imgur.com/HtMS0Jg.png)


### Dataflow Diagram
- 특정 시스템의 프로세스 전반에서 데이터의 흐름을 시각적으로 나타냄
- DFD는 프로세스에 입력 및 출력되는 정보의 종류와 데이터가 저장되는 위치를 보여줌
- 데이터 흐름도의 목적은 구성 요소 간의 정보 이동을 설명하면서 범위와 경계가 있는 시스템 전체를 보는 것
- 초점은 프로세스 흐름이 아닌 시스템 전체의 데이터 흐름에 있다. DFD를 통해 독자는 관련된 정보의 종류와 흐름을 파악하여 시스템이 어떻게 작동하는지 쉽게 확인할 수 있다.
![|675](https://i.imgur.com/y3g07ql.png)
