### Parallel Processing
친구 두명이 가세해 한 사람이 한 아티클씩, 세개의 아티클을 동시에 쓰는 형태를 병렬처리라고 부름
- 파이썬 에서는 멀티 코어로 다중 프로세스를 사용하는 상황이 이에 해당
![|700](https://i.imgur.com/45x0Pjb.png)

병렬 처리는 앞에서의 동시 처리에 포함되는 개념이다. (병렬 처리는 동시 처리의 하위 개념)
즉, 모든 병렬 처리는 동시 처리이기는 하나, 동시처리라고해서 모두가 병렬처리 인것은 아닙니다.
- 병렬 처리는 여러 작업을 **물리적으로 동시에 실행** → 병렬 처리는 물리적 자원을 활용하여 작업을 동시에 실행하므로 논리적으로도 동시 처리
- 동시 처리는 여러 작업이 **논리적으로 동시에 실행** → 동시 처리가 반드시 물리적으로 동시에 실행되는 것은 아니며, 작업 스케줄링을 통해 논리적으로만 동시에 실행될 수도 있음

### How Python work with Concurrency 
- Multi-Threading
- Multi-Processing
- Event-Loop
- Coroutine

<mark style="background: #C6AB16;">동시 처리를 도입할 때 어느 방법이 적합한가는 그 처리가 CPU Bound 처리, I/O Bound 처리 인지에 따라 결정된다.</mark>
#### CPU Bound 처리
- 암호화(복호화), 숫잣값계산등 CPU의 자원을 사용해 계산을 수행하는처리
- 여러 코어를 동시에사용해병렬처리를할수있는 다중프로세스가유효
- 파이썬에는 GIL이있으므로 다중스레드,이벤트 루프를 통한 처리 고속화는 기대할 수없음

#### I/O Bound 처리
- 데이터베이스접속, Web API 이용등 통신에 의한 대기 시간이 발생하는처리
- 다중프로세스(multiprocessing), 다중스레드(concurrent.future), 이벤트루프(asyncio) 모두 유효
- 어떤방법을선택할지는오버헤드나구현난이도를고려해서결정

일반적으로 실행시의 오버헤드가 큰순서대로 나열하면 다중 프로세스 → 다중스레드 → 이벤트루프 순이다.

### Relationship between Concurrency & Asynchronous 
파이썬에서는 함수나 메서드를 호출하면 일반적으로 호출한 대상의 처리를 모두 완료할 때 까지 호출자는 다음처리를 진행하지않습니다. 이러한 처리를 일반적으로동기처리 synchronousprocesing 라고부릅니다.

한편 비동기처리 asychronousprocessing 에서는 호출한대상이 처리를하는중이라도, 호출자는 다음처리를 진행할수있습니다. 호출한 대상의 결과를얻기전에 호출자는 다음처리를진행하기 때 문 에 처 리 완 료 알 림 이 나 결 과 는 콜백 &l b a c k 함 수 등 을 사 용 해 호 출 자에게알려줍니다. 

호출자와 호출 대상이 동시에 처리를 실행하기 때문에 비동기처리를 사용할때는 동시 처리를 한다고 말할수있습니다.

#### Sync vs Async
Sync: 작업을 다른 스레드에 보내고 해당 작업이 끝날 때까지 기다린 후(block) 다음 작업을 시작한다.
![](https://i.imgur.com/wLa1chq.png)


Async: 작업을 다른 스레드에 보내고 바로 다음 작업을 시작한다.
![](https://i.imgur.com/1HJH3uB.png)



#### Serial vs Concurrent
Serial: 다른 하나의 스레드로만 작업을 보낸다. 작업의 순서를 지켜야 하는 경우 사용한다.
![](https://i.imgur.com/JFWn9ye.png)


Concurrent: 다른 여러 개의 스레드로 분산하여 작업을 보낸다.
![](https://i.imgur.com/PKkEqXj.png)

> [!tip] 
> 파이썬에서 다중스레드를 사용할때 등장하는 키워드로 GIL (Global Interpreter Lock, 전역인터프리터록) 이있습니다. GIL은 이름 그대로 파이썬 인터프리터 전체에서 공유하는 잠금기능입니다. 여러스레드가 있을때, GIL을 얻은하나의 스레드만 파이썬의 바이트코드를 실행할수 있도록 설계 되어있습니다.' 파이썬의 이러한 구조적 특성상 다중스레드를 이용한동시 처리에서는 CPU 바운드 처리에서 빠른속도를 기대할 수 없습니다.


> [!faq] **`비동기`와 `동시`는 같은 말인가?**
> 비동기: 작업을 보내는 스레드에 관련된 개념이다. 작업을 보내는 스레드가 보낸 작업이 끝나기를 기다리는지 아닌지가 중요하다.  
동시: 작업을 받는 스레드에 관련된 개념이다. 작업을 받는 스레드가 한 개인지 아닌지가 중요하다.

> [!faq] **`비동기`와 `동시`는 무엇과 관련이 있는 개념인가?**
> 비동기: 서버와의 통신(네트워크 작업)  
동시: 성능, 반응성, 최적화

> [!faq] **`동시(concurrent)`와 `병렬(parallel)`은 같은 말인가?**
> 동시: 싱글 코어에서 멀티 스레드를 동작시키는 방식이다. 실제로 여러 작업이 동시에 진행되지는 않는다.  
병렬: 멀티 코어에서 멀티 스레드를 동작시키는 방식이다. 실제로 여러 작업이 동시에 진행된다.

## EventLoop - Asyncio
이벤트루프를 사용하여 단일 스레드에서도 동시 처리가 가능하기떄문에 성능면에서도 효율성이 높아진다.

### Coroutine
처리 도중에 중단, 다시 시작.

asyncio모듈을사용하려면 반드시 코루틴coroune이 필요합니다. 

> [!note] 
> 코루틴은 서브루틴 Subroutne과 같이 일련의 처리를 모아둔것입니다. 
> 서브루틴은 파이썬에서는 함수에 해당 한다.

서브루틴은 파이썬에서는 함수에 해당 하고, 한번호출되면앞에서부터마지막까지(혹은도중에무언가를반환할때까지) 한번에실행합니다. 
이특성을 이용하면여러처리가동시에이루어지도록구현할수있습니다.

**예를들어, Web API를사용하는코루틴은HTTP요청을송신하면응답이돌아올때까지다음처리를진행하지않습니다.** 
**이럴때는이코루틴을중단시켜, 다른코루틴을동작시키는것에CPU자원을활용할수있습니다.** 

물론, 응답이돌아오면중단한코루틴 도적절한타이밍에서다시 처리하기시작합니다.

#### await 문을 사용해 코루틴 호출과 동작
처리를중단시키는포인트는IVO 처리에의한대기시간이발생하는위치와 그처리를 호출하는위치입니다. 

여기에서는예시로WebAPI를사용합니다.
먼저WebAP를사용하는처리를코루틴으로정의합니다. 그리고그코루틴을호출하 는처리도역시코루틴으로정의합니다. 이와같이구현해가면필연적으로코루틴안에 코루틴을호출하는위치가생깁니다. 이곳이처리를중단할수있는포인트로, 코드상에 서는await 키워드를기술합니다. await 키워드가있더라도반환값은일반적인함수를호출할때와동일하게다룰수있습니다.

구 체 적 인 구 현 사 례 를 확 인 해 봅 니 다 . 다 음 코 드 는W e b A P I 를 사 용 하 는 C a l l _ w e b -
a p i ( ) 와 그 것을 사 용한 a s y n c_ d own l o a d ( ) 라 는 두 개의 코 루틴 을 정의하 고 있 습니
다.단,이책에서의코루틴calL_web_api() 는실제로는요청을던지지않고,코루틴 asyncio.sLeep()을 호출해시간이걸리는 처리를 시뮬레이션했습니다. 
또한, 응답이 돌아올때까지걸리는시간은요청마다다르므로random.random() 함수를사용해구현합니다.

```python
import asyncio
import requests

async def call_api(url):
    print(f"send a request{url}")

    await asyncio.sleep(random.random())
    print(f"got a response: {url}")
    return url


async def async_download(url):
    response = await call_api(url)
    return response


async def main():
    task = asyncio.gather(
        async_download("https://twitter.com"),
        async_download("https://facebook.com"),
        async_download("https://instagram.com"),
    )
    return await task


result = asyncio.run(main())
```

처리흐름을따라가봅니다.
1. gather() 함수의인수로전달한최초의코루틴을실행
2. 그처리중에ayncio.sLeep()까지진행한뒤처리를중단
3. 두번째코루틴동작을시작 (async.sleep()으로처리를중단한이유는I/O처리에따른대기시간이발생하기때문)
4. 두번째코루틴도asyncio.sleep()까지진 행한뒤처리를중단
5. 세번째코루틴동작을시작합니다. 그리고세번째코루틴이 asyncio.sleep()까지진행한뒤처리를중단한뒤에는, 응답이올때까지대기
6. 그뒤응답이돌아오면재개할수있는코루틴부터다시순차처리를시작
7. 가장 마지막의응답처리까지완료하면gather() 함수는리스트를반환 → 이때리스트 순서는gather() 함수에전달한코루틴순서와일치


#### time.sleep vs asynio.sleep
time.sleep
```python
------------------------------- 타임라인 -------------------------------->

코루틴1: |----작업 중----|  time.sleep() (3초 동안 멈춤)   | 작업 종료 |

코루틴2:                   기다리는 중...                 |----작업 시작----|

전체 소요 시간: 코루틴1(작업 시간 + 3초 대기) + 코루틴2 작업 시간
```

await sleep
```python
------------------------------- 타임라인 -------------------------------->

코루틴1: |----작업 중----|   await asyncio.sleep(3) 중지 →   다시 작업   | 작업 종료 |

코루틴2:                  → 작업 시작 중...                  |   끝

전체 소요 시간: 병렬로 처리된 작업 시간(대기 없이 교대로 처리됨)
```
