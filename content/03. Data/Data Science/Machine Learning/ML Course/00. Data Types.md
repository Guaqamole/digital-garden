### 1.1 Label Encoding
Label Encoding은 범주형 변수의 **각 범주(카테고리)에 고유한 정수를 할당**함으로써, 기계 학습 모델이 이해할 수 있는 형태로 데이터를 변환하는 것을 의미합니다.

이 과정은 scikit-learn 라이브러리의 preprocessing 모듈에 있는 LabelEncoder 클래스를 통해 쉽게 구현할 수 있습니다. LabelEncoder는 범주형 변수에 나타나는 각 범주를 알파벳 순 또는 데이터에 처음 나타나는 순서에 따라 정렬한 후, 0부터 시작하는 연속적인 정수 값으로 변환합니다. 이때, 할당되는 정수의 범위는 범주의 총 개수에 따라 결정됩니다. 예를 들어, 4개의 범주가 있다면 각각 0, 1, 2, 3으로 표현됩니다. 즉, 가장 큰 숫자는 '범주의 개수(4) - 1'인 3이 되며, 이는 총 범주의 수를 기반으로 한 할당 방식을 나타냅니다. 모델은 이렇게 변환된 숫자형 표현을 사용하여 데이터를 분석하게 됩니다

#### 1.1.1 학습 데이터에서 범주형 변수 인코딩 실습
범주형 변수인 'Brand', 'Model', '정비 이력등급' 에 대하여 scikit-learn의 LabelEncoder를 통해 인코딩 해 봅시다.

```python
from sklearn.preprocessing import LabelEncoder
import numpy as np

categorical_var = ['Brand',  'Model', '정비 이력등급']

label_encoders = {}

for col in categorical_var:
    le_train = LabelEncoder()

    train_used_car[col] = le_train.fit_transform(train_used_car[col])
    label_encoders[col] = le_train
    
display(train_used_car.head())
```

#### 1.1.3 학습 데이터에 없는 범주 올바르게 처리하기
"학습 데이터에 없는 범주"란? 학습 데이터셋에는 여러 범주형 변수가 포함되어 있고, 각 변수에는 다양한 범주(카테고리)가 존재합니다. 예를 들어, 자동차 데이터셋에서 '색상'이라는 범주형 변수가 있다면, 이 변수의 범주는 '빨강', '파랑', '녹색' 등이 될 수 있습니다.

그런데, 학습 데이터셋에 없는 테스트 데이터셋을 모델에 입력할 때, 학습 데이터셋에는 없던 새로운 범주가 포함되어 있을 수 있습니다. 예를 들어, 테스트 데이터셋에 '보라'라는 새로운 색상이 있을 수 있습니다. 이 '보라'라는 색상은 학습 데이터셋에는 없었기 때문에, 모델은 이를 어떻게 처리해야 할지 모릅니다. 이러한 경우를 "학습 데이터에 없는 범주"라고 합니다.

```python
test_ex2 = test_used_car.copy()

# train_used_car 데이터셋의 라벨 인코더 클래스에 '기타' 범주를 다시 추가
for le in label_encoders.values():
    le.classes_ = np.append(le.classes_, 'Other')

# 새로운 범주값을 '기타'로 매핑하고 라벨 인코더를 적용하는 과정을 하나의 루프로 합치기
for col in categorical_var:
    # 새로운 값들을 '기타'로 매핑
    test_ex2[col] = test_ex2[col].apply(lambda x: x if x in label_encoders[col].classes_ else 'Other')
    # 라벨 인코더 적용
    test_ex2[col] = label_encoders[col].transform(test_ex2[col])

# 변환된 test_used_car 데이터셋 보여주기
display(test_ex2.head())
```

### 2.4 레이블 인코딩의 한계와 단점
**위와 같이 라벨 인코딩(Label Encoding)하는 것에 큰 문제는 없을까요?**

위에서 인코딩 한 결과는 'education'(교육 수준) 데이터의 **'등급', 혹은 '순서'로서의 의미 를 학습 과정에 담을 수가 없습니다.**  
학력 등급은 일정한 순서와 계층적 관계를 가지고 있고, 이것이 '연간 소득'이라는 타겟 변수와 연관성이 있다고 가정하는 것이 합리적일 수 있습니다.  
예를 들어, 학사 학위를 취득한 사람은 대학 수료 미만인 사람보다 **"더 높은"** 학력을 가지고 있다고 볼 수 있습니다.  
만일 이러한 순서, 등급의 의미를 담아 인코딩 함으로서 모델이 이러한 정보를 학습하고 예측에 활용하기 원한다면, LabelEncoder은 적절하지 않습니다.


### 3. '순서형'(ordinal) 범주형 변수답게 인코딩 하기
#### **3.1 Direct Mapping 통한 인코딩**

### 4 '순서형'(ordinal) 범주형 변수답게 인코딩 하기(1)
#### **4.1 Ordinal Encoder를 활용한 인코딩**
이번에는 scikit-learn의 OrdinalEncoder를 사용하여 교육 수준(education)을 인코딩하는 방법을 배웁니다.

```python
from sklearn.preprocessing import OrdinalEncoder

train_ex3 = train_income.copy()
```

### 5. 결론
순서형 범주형 변수, 특히 많은 고유 카테고리를 가진 경우, 데이터 분석과 모델링에서 중요하고 세심한 처리가 필요한 부분입니다. 이러한 변수들은 고유한 범주(카테고리)가 많기 때문에, 이들을 어떻게 효과적으로 인코딩하는지는 모델의 성능에 결정적인 영향을 미칠 수 있습니다. 따라서, 순서형 범주형 변수를 다룰 때는 이에 적합한 인코딩 방법을 선택하는 것이 필수적입니다.

다음은 초보자들이 순서형 범주형 변수를 다룰 때 고려야 할 몇 가지 중요한 점들입니다.

**[1] 고유 범주 수 축소:**  
순서형 범주형 변수에 대한 첫 번째 단계는 가능하다면 범주의 수를 줄이는 것입니다.  
이는 통계적 분석이나 도메인 지식을 활용하여 유사한 범주를 통합함으로써 이루어질 수 있습니다.  
예를 들어, 빈도수가 낮은 범주들을 더 큰 범주로 통합하거나, 의미론적으로 유사한 범주들을 하나로 합치는 것입니다.  
이는 모델이 데이터를 더 잘 이해하고, 복잡도를 감소시키는 것에 매우 '실질적'인 영향을 줄 수 있습니다.

**[2] 의미 있는 수동 인코딩:**  
순서형 범주형 변수의 경우, 단순한 Label Encoding보다는 변수의 순서나 등급을 반영할 수 있는 Direct Mapping이나 Ordinal Encoder를 사용하는 것이 좋습니다. 특히 Linear Regression, Ridge, Lasso와 같은 선형 모델에서는 이러한 순서 정보를 잘 반영하지 않으면 변수 간의 관계를 제대로 파악하지 못해 모델의 성능이 왜곡될 수 있으므로 순서를 반영한 인코딩이 필요합니다.

이러한 인사이트를 바탕으로, 순서형 범주형 변수를 다룰 때는 해당 변수의 성격을 고려하여 적절한 인코딩 전략을 선택하는 것이 중요합니다. 이를 통해 모델의 성능을 최적화하고, 데이터 분석의 정확도를 높일 수 있습니다. 범주형 변수의 인코딩은 데이터 과학의 핵심적인 부분이므로, 이에 대한 이해와 적절한 적용은 데이터 분석의 성공에 큰 기여를 할 것입니다.


## Nominal Encoding
명목형 범주형 변수를 처리하는 대표적인 인코딩 기법인 One-Hot Encoding과 Binary Encoding에 대해 학습하고, 실무 데이터에 적용하는 방법을 실습합니다.

One-Hot Encoding은 명목형 범주형 변수를 이진 특성으로 변환하는 기법입니다. 그러나 각 변수가 다수의 고유 범주를 가지는 경우, 이 방식의 사용은 문제를 일으킬 수 있습니다. 이에 대한 효율적인 해결책을 찾아볼 필요가 있습니다.

Binary Encoding은 이러한 문제를 해결하는 데 적합한 대안입니다. 이 방식은 범주형 정보를 보존하면서도 변수의 수를 효과적으로 관리합니다.

### 1. 원 핫 인코딩 (One-Hot Encoding)
이전 단계에서 우리는 레이블 인코딩(Label Encoding)을 적용하여 'Brand'와 'Model'과 같은 명목형 변수를 수치적으로 변환했습니다. 하지만 이 방법은 데이터에 순서나 등급 같은 부적절한 의미를 부여할 수 있어, 모델의 학습 및 예측 성능에 왜곡을 일으킬 위험이 있습니다. 이에 대한 대안으로, 원-핫 인코딩(One Hot Encoding)은 각 범주를 독립적인 이진 특성으로 변환함으로써 이러한 문제를 해결합니다.

#### 1.3 학습 데이터에 없는 범주 올바르게 처리하기
**OneHotEncoder 클래스의 handle_unknown='ignore' 매개변수**

앞서 발생한 문제를 해결하기 위해, OneHotEncoder 클래스의 handle_unknown='ignore' 옵션을 활용합니다.  
이 설정은 학습 데이터셋에 존재하지 않는 새로운 범주를 만나더라도 오류 없이 처리하도록 도와줍니다. 실제 데이터 처리 과정에서 예상치 못한 새로운 범주가 등장하는 상황에 대비해, handle_unknown='ignore' 설정을 사용하는 것이 바람직합니다.

이제, 이 설정을 적용하여 학습 데이터셋에 대한 원-핫 인코딩을 수행하고, 같은 인코더를 테스트 데이터셋에 적용해 보겠습니다.

```python
train_ex2 = train_used_car.copy()

encoder_ex2 = OneHotEncoder(sparse_output = False, handle_unknown ='ignore' )

train_encoded_ex2 = encoder_ex2.fit_transform(train_ex2[['Brand','Model']]) 

# Convert the encoded features into a DataFrame
encoded_columns_ex2 = encoder_ex2.get_feature_names_out(['Brand', 'Model'])
train_encoded_df2 = pd.DataFrame(train_encoded_ex2, columns=encoded_columns_ex2)
```

#### 1.4 더미(dummy) 변수의 함정과 OneHotEncoder의 Drop 옵션
원-핫 인코딩을 적용한 결과, 'Brand' 컬럼은 'Brand_Ford', 'Brand_Honda', 'Brand_Toyota'라는 세 개의 컬럼으로 변환되었습니다. 이러한 변환을 보며 다음과 같은 의문이 들 수 있습니다:

**_'세 개의 컬럼 모두 필요한가? 두 개의 컬럼만으로도 충분하지 않을까?'_**

실제로, 세 개의 컬럼을 모두 사용하면, 적어도 두 컬럼 간에는 일종의 연관성이 존재하게 마련입니다. 예를 들어, 'Brand_Ford'가 0이라면, 이는 자동적으로 'Brand_Honda' 또는 'Brand_Toyota' 중 하나가 1이 될 가능성이 높다는 것을 의미합니다. 이처럼 컬럼 간에 상호 의존적인 관계가 형성되는 것을 '다중공선성'이라고 합니다. 이는 모델의 예측력을 저하시키고 해석을 어렵게 만드는 주요 원인이 됩니다."

이러한 문제의식은 **'더미 변수의 함정'** 이라고 불리는 현상을 지적하는 것입니다.

Scikit-learn은 이 문제를 해결할 수 있는 수단를 제공합니다. 바로 OneHotEncoder의 drop 매개변수입니다. drop='first'로 설정하면, 첫 번째 카테고리를 자동으로 삭제하여 다중공선성의 위험을 줄이면서도 필요한 정보를 모두 포함시킬 수 있습니다.

```python
import pandas as pd
from sklearn.preprocessing import OneHotEncoder  

train_ex3 = train_used_car.copy()

encoder_ex3 = OneHotEncoder(sparse_output = False, drop = 'first', handle_unknown = 'ignore')
train_encoded_ex3 = encoder_ex3.fit_transform(train_ex3[['Brand','Model']]) 

# Convert the encoded features into a DataFrame
encoded_columns_ex3 = encoder_ex3.get_feature_names_out(['Brand', 'Model'])
train_encoded_df3 = pd.DataFrame(train_encoded_ex3, columns=encoded_columns_ex3)

train_ex3 = pd.concat([train_ex3, train_encoded_df3], axis=1).drop(['Brand', 'Model'], axis=1)

test_ex3 = test_used_car.copy()
test_encoded_ex3 = encoder_ex3.transform(test_ex3[['Brand', 'Model']])
test_encoded_df3 = pd.DataFrame(test_encoded_ex3, columns=encoded_columns_ex3)

test_ex3 = pd.concat([test_ex3, test_encoded_df3], axis=1).drop(['Brand', 'Model'], axis=1)

display(encoded_columns_ex3)
display(train_ex3.head())
display(test_ex3.head())
```

#### 3.2 바이너리 인코딩(Binary Encoding)
이렇게 고유 범주의 갯수가 많은 명목형 변수를 인코딩할 수 있는 대표적인 기법이 바이너리 인코딩(binary encoding)입니다.  
이 기법은 데이터의 차원을 효과적으로 줄이면서 각 범주를 명확하게 표현할 수 있는 장점을 가지고 있습니다.

바이너리 인코딩은 각 범주를 레이블 인코딩으로 변환한 후, 이진수로 표현하여 범주의 수에 비례하지 않는 고정된 길이의 열을 생성합니다. 이는 차원의 증가를 상당히 제한하며, 동시에 각 범주를 효율적으로 표현할 수 있게 합니다.

![](https://i.imgur.com/CizxlHv.png)

category_encoders 라이브러리의 BinaryEncoder 클래스는 이러한 바이너리 인코딩 과정을 간편하게 수행할 수 있게 해줍니다. 이 라이브러리는 각 범주를 자동으로 레이블 인코딩하고, 이를 이진수 형태로 변환하여 새로운 열을 생성합니다. 이를 통해, 우리는 'occupation' 컬럼을 효과적으로 인코딩하고, 모델의 성능과 메모리 효율성을 동시에 개선할 수 있습니다.

### 4. 결론
범주형 변수의 인코딩은 데이터 전처리에서 중요한 단계입니다, 특히 많은 범주를 가진 명목형 변수의 경우, 매우 신중하게 고유 카테고리의 영향도 및 분석 과정이 매우 중요합니다. 이러한 문제를 해결하는 데 있어 다음과 같은 전략을 제안합니다:

- **범주의 간소화:** 데이터 탐색(EDA)과 도메인 전문 지식을 활용하여 유사한 범주를 통합하고, 빈도가 낮은 범주를 병합하는 접근법은 범주의 수를 효과적으로 줄일 수 있습니다. 이러한 방법은 단순히 모델의 복잡성을 감소시키는 것을 넘어, 인코딩 기법 자체가 미치는 영향보다 더 큰 향상을 모델 성능에 가져올 수 있습니다.
    
- **바이너리 인코딩 적용:** 간소화된 범주 구조를 가진 후에는 바이너리 인코딩 방식을 적용하는 것이 권장됩니다. 바이너리 인코딩은 다수의 범주를 가진 변수에 대해 원-핫 인코딩에 비해 더 메모리 효율적이며, 이진 수 조합을 통해 각 범주를 표현함으로써 생성되는 새로운 변수의 수를 최소화합니다.
    
- **고급 인코딩 기법 고려:** 본 학습에서는 다루지 않았지만, 타깃 인코딩(Target Encoding)과 같은 고급 인코딩 기법도 주목해야 합니다. 이러한 기법은 종속 변수(타깃)와의 관계를 기반으로 각 범주를 인코딩하며, 데이콘 대회 혹은 kaggle 대회에서 인기 있는 기법으로 자주 사용되고 있습니다.

# Outliers

## Basics

### 1.이상치란?

이상치는 말 그대로 일상에서 흔히 보이는 것과 조금 다른 것을 말해요.  
이런 특별한 녀석들은 자주 보이지 않고, 평범한 것들과는 판이하게 다른 경우가 많죠.

그림을 한번 봐볼까요? 파란색 이모지가 얼마나 눈에 띄는지 보세요.  
주위에 있는 노란색 이모지들은 다 비슷비슷해 보이죠? 이 친구들은 모두 일상에서 잘 어울리고 있는 평범한 친구들이에요.  
그런데 이 파란색 이모지는 다른 모습 덕분에 한눈에 '어, 새로 왔구나!' 하고 알아챌 수 있답니다.

데이터 세상에서도 비슷해요.  
대부분의 데이터 포인트들은 비슷한 패턴을 보이지만, 가끔은 '이 데이터 포인트는 좀 다른데?' 싶은 경우가 있죠.  
바로 그 '다른 녀석', 이 파란색 이모지처럼 말이죠. 이런 녀석들은 분석할 때 특별히 주목해야 해요.  
왜냐하면 가끔은 이런 이상치들이 중요한 정보를 가지고 있을 수도 있으니까요.

노란색🟡 이모지들은 '우리가 여기의 주인공'이라며 평범한 데이터의 흐름을 따르지만,  
파란색🔵 이모지는 '나는 좀 특별해'라며 새로운 관점이나 중요한 정보를 줄 수 있는 이상치를 나타내요.  
데이터 분석에서 이런 이상치를 잘 찾아내고, 그 이유를 파악하는 게 중요하죠.

예를 들어, 회사에서 매달 비슷한 수익을 내다가 갑자기 어느 달에 수익이 평소보다 열 배로 치솟았다면, 이는 정말로 중요한 사건이 될 수 있어요.  
이게 단순한 실수인지 아니면 실제로 놀라운 성과를 이룬 것인지 파악하는 것은 중요하죠.

데이터 분석에서 이상치를 어떻게 처리하는지가 중요해요.  
잘못 다루면 전체 데이터의 패턴을 잘못 해석할 수 있고, 결국 잘못된 결론을 내릴 수도 있답니다.

결론적으로, 데이터 분석에서 이상치를 제대로 파악하고 적절하게 다루는 것은 데이터의 질을 높이고 정확한 분석 결과를 얻기 위해 정말 중요한 일이에요.  
이상치 처리는 데이터 분석의 결과와 품질에 큰 영향을 미치기 때문에, 이를 잘 다루는 방법을 알고 있는 것은 데이터 분석가에게 필수적인 능력이랍니다!👊

### 2.이상치는 왜 생기는 걸까?🤔

이상치가 왜 생길까요? 우리 일상에서 간혹 '이건 좀 다르다' 싶은 순간들이 있죠.  
그 원인은 여러 가지일 수 있어요.

1️⃣ 첫 번째는, 아주 **인간적인 실수**에서 비롯될 수 있어요.  
데이터를 입력할 때 오타를 치거나, 온도를 재려고 했는데 온도계가 맛이 간 경우죠.  
이런 실수들은 누구에게나 일어날 수 있어요.

2️⃣ 두 번째, **데이터 자체가 손상**되었을 수도 있어요.  
전송 중에 데이터가 깨지거나, 저장 과정에서 문제가 발생한 거죠.  
이런 기술적인 문제들도 이상치의 원인이 될 수 있답니다.

3️⃣ 세 번째 이유는, 실제로 뭔가 **예외적인 일**이 일어났기 때문일 수도 있어요.  
예를 들어, 보통은 조용한 마을에 축제가 열려서 갑자기 소음이 많아진 경우를 생각해볼 수 있죠.

데이터는 각자의 독특한 이야기를 가지고 있어서, 이상치를 찾는 '하나의 정답'은 없어요.  
데이터의 세세한 부분을 잘 아는 사람이나 해당 분야의 전문가가 직접 살펴보는 게 중요하죠.  
통계적인 방법을 통해 드문 값을 찾는 건 가능하지만, 그 값들을 그냥 이상치라고 단정 지어 버리면 안 돼요.  
이상치가 왜 생겼는지, 전체적인 데이터 패턴에서 어떤 위치를 차지하는지를 이해해야 하니까요.

### 3.이상치의 유형

이상치는 대개 두 가지 유형으로 나눌 수 있습니다.

1️⃣ **단변량 이상치**

이건 단 하나의 특징만 봐서 찾는 건데요, 예를 들면 사람들 키만 놓고 봤을 때, 평균적인 키에서 너무 멀리 떨어져 있는 경우를 말해요.  
쉽게 말해, 대부분 사람들이 150cm에서 190cm 사이인데, 갑자기 250cm의 거인이 나타난다면, 그 사람은 단변량 이상치라고 할 수 있죠.

2️⃣ **다변량 이상치**

이건 여러 특징을 함께 봐서 찾는 건데, 사람의 키와 몸무게를 같이 고려하는 거예요.  
대부분의 사람들이 키 대비 몸무게가 비슷비슷한데, 어떤 사람은 키에 비해 몸무게가 너무 적거나 많으면 그 사람은 다변량 이상치에 속하게 되죠.  
예를 들어, 180cm에 50kg이거나 또는 160cm에 100kg인 경우가 이에 해당할 거예요.

이렇게 이상치를 찾는 것은 데이터를 이해하는 데 정말 중요해요.  
우리가 사람들 사이에서 특이한 패턴을 발견하듯이, 데이터 속에서도 그런 특이한 패턴을 찾아내는 거죠.

### 4.이상치가 데이터 집합에 미치는 영향 😢

데이터에서 이상치를 발견하는 건, 마치 레시피에 없는 재료가 음식 속에 섞여 있는 것과 같아요.  
이상치 때문에 데이터 분석이나 예측 모델이 받는 영향을 설명해 볼게요.

1️⃣ **예측의 오차가 커져요**

이상치가 있으면 데이터가 제각각 흩어져 버려서, 예측하는 데 필요한 패턴을 찾기가 어려워져요.  
이건 마치 날씨 예보를 할 때 갑자기 이상한 기후 현상이 끼어들어서 예측이 어긋나는 것과 비슷해요.

2️⃣ **데이터의 일반적인 리듬이 깨져요**

데이터에 일정한 리듬이 있어야 하는데, 이상치가 그 리듬을 깨트릴 수 있어요.  
이건 마치 시계가 정확한 시간을 가리키지 못하는 것처럼, 분석이나 예측의 정확도가 떨어지게 만들죠.

3️⃣ **결과가 한쪽으로 치우쳐요**

이상치는 평균 같은 중요한 지표를 한쪽 방향으로 끌고 가서, 실제보다 더 많거나 적게 보이게 할 수 있어요.  
마치 사진을 찍을 때 한쪽으로 너무 치우쳐서 찍어서 전체 장면이 제대로 안 보이는 것과 같죠.

4️⃣ **분석의 기본 규칙들이 흔들려요**

분석이나 모델링을 할 때는 데이터가 일정한 규칙을 따른다고 가정하는데, 이상치 때문에 그 규칙이 깨질 수 있어요.  
이것은 마치 룰이 정해진 게임을 할 때 누군가가 갑자기 규칙을 어기는 것처럼 혼란을 주죠.

이런 이유로, 데이터를 분석할 때는 이상치를 조심스럽게 다뤄야 해요.  
이상치를 그냥 두면, 우리가 데이터로부터 얻는 통찰이나 예측이 잘못될 수 있거든요.

### 5.이상치 없는 데이터 vs. 이상치 있는 데이터

이상치가 없는 데이터 집합과 이상치가 있는 데이터 집합을 비교해 보면서 이상치가 데이터 분석에 미치는 영향을 더 잘 이해해보아요.

  

![Image](https://r2-images.dacon.co.kr/project/126/content/%E1%84%8B%E1%85%B5%E1%84%89%E1%85%A1%E1%86%BC%E1%84%8E%E1%85%B5_%E1%84%91%E1%85%A7%E1%86%BC%E1%84%80%E1%85%B2%E1%86%AB%E1%84%91%E1%85%AD%E1%84%8C%E1%85%AE%E1%86%AB%E1%84%91%E1%85%A7%E1%86%AB%E1%84%8E%E1%85%A1.png)

- **이상치가 없는 경우** , 데이터가 대체로 비슷한 범위에 있어요.  
    평균 값은 데이터들의 '평균'적인 값인 5에 가깝게 나와요.  
    표준 편차가 작기 때문에 데이터가 대체로 평균 주변에 몰려 있어요.

이러한 비교를 통해 이상치가 데이터 분석에 미치는 영향을 명확하게 이해할 수 있어요.  
이상치가 있는 경우, 평균과 표준 편차와 같은 통계적 지표가 왜곡되고 데이터의 중심 경향과 분산을 왜곡시킬 수 있어요.  
그러므로 데이터 분석 시에는 이상값을 신중하게 고려해야 합니다.

### 2. 이상치를 발견하는 방법들 😇

이상치를 어떻게 찾아낼 수 있을까요? 여러 가지 방법이 있지만, 여기서는 네 가지 주요 기법을 통해 이상치를 발견하는 방법을 자세히 살펴보겠습니다.

#### ✅ 단변량 이상치 탐지(스테이지2):

**1. Z-Score (Z-점수)** Z-Score는 데이터에서 표준 편차를 활용해 이상치를 감지하는 간단하면서도 강력한 방법입니다. 이 방법은 데이터를 표준화하고, 각 데이터 포인트가 평균으로부터 얼마나 떨어져 있는지를 계산하여 이상치를 식별합니다. 특히 표준화된 데이터 세트에 효과적입니다.

**2. IQR (Interquartile Range, 사분범위)** IQR은 데이터의 중앙값을 기준으로 하여 '정상 범위'를 벗어나는 데이터 포인트를 찾아냅니다. Q1(제1사분위수)과 Q3(제3사분위수)를 계산하고, 이를 기반으로 IQR을 구한 후, IQR을 이용하여 이상치를 탐지합니다.

#### ✅ 다변량 이상치 탐지(스테이지3):

**3. DBSCAN (Density-Based Spatial Clustering of Applications with Noise)** DBSCAN은 데이터 포인트들을 그룹화해서 이상치를 식별하는데 사용되는 클러스터링 알고리즘입니다. 데이터 포인트의 밀도를 기반으로 하며, 주변 데이터 포인트와의 관계를 고려하여 이상치를 찾아냅니다. 이 방법은 다양한 데이터 구조에서 유용합니다.

**4. LOF (Local Outlier Factor)** LOF는 데이터 포인트의 '지역적 밀도'를 측정하고, 이를 주변 포인트의 밀도와 비교하여 이상치를 탐지합니다. 주변 데이터 포인트와의 밀도 비율을 계산함으로써 이상치를 식별하며, 이 방법은 데이터의 지역적 밀도가 다를 때 효과적입니다.

이상치 탐지는 데이터 분석의 핵심 부분이며, 위에서 설명한 기법들은 다양한 데이터셋과 상황에 적용할 수 있습니다. 이러한 방법들을 이용하여 데이터에 숨어 있는 이상치를 효과적으로 식별할 수 있습니다.

### 3. Z-Score를 활용하여 이상치 발견해보기!

#### 3.1. Z-Score 란?

Z-Score는 데이터 포인트가 데이터 세트의 평균으로부터 얼마나 떨어져 있는지를 측정합니다.  
이를 통해 데이터 포인트가 전체 데이터 분포에서 어떤 위치에 있는지 파악할 수 있습니다.  
이 방법은 데이터 세트 내에서 각 데이터 포인트의 상대적인 위치를 수치화하여, 데이터 포인트가 평균적인 범위 내에 있는지, 아니면 평균에서 벗어나 이상한 값을 가지는지를 판단하는 데 사용됩니다.

Z-Score는 다음과 같은 공식으로 계산됩니다.

![](https://i.imgur.com/Bk5ytFe.png)


#### 3.2. Z-Score의 해석

데이터가 정규 분포를 따른다고 가정할 경우 아래와 같이 해석할 수 있습니다.

- **Z-Score = 0**: 데이터 포인트가 평균값에 정확히 일치합니다.
- **Z-Score > 0**: 데이터 포인트가 평균값보다 높습니다.
- **Z-Score < 0**: 데이터 포인트가 평균값보다 낮습니다.

![](https://i.imgur.com/MDWNsVJ.png)


일반적으로, Z-Score가 매우 높거나 낮은 값(예를 들어, ±2 또는 ±3 이상)은 데이터 세트에서 이상치일 가능성이 높다고 간주됩니다.  
이런 값들은 나머지 데이터와 상당히 다르기 때문에 특별한 주의가 필요합니다.

위 그림은 Z-score를 사용한 이상치 탐지를 설명하는 정규 분포를 나타냅니다.  
Z-score 값이 -3 이하 또는 3 이상인 지역은 이상치로 간주되며, 붉은색으로 표시되어 있습니다.  
-2와 2 사이의 값들은 이상하지 않은(normal) 범위로 간주되며, 노란색으로 표시되어 있습니다.  
-2와 -3 사이, 2와 3 사이의 값들은 다소 이상하다고 여겨지는(moderately unusual) 범위로, 주황색으로 표시되어 있습니다.

#### 3.3. Z-Score 를 이용한 이상치 탐지 실습

1. **Z-Score 직접 계산 후 이상치 제거**: 이 방법에서는 데이터 세트의 평균과 표준편차를 사용하여 각 데이터 포인트의 Z-Score를 수동으로 계산합니다. 이후 설정한 Z-Score 임계값(예를 들어, ±2 또는 ±3)을 넘는 데이터 포인트를 이상치로 판단하고 제거할 수 있습니다.

```python
def out_zscore(data, threshold=3):
    mean = np.mean(data)
    std = np.std(data)
    zscores = [(x - mean) / std for x in data]
    outliers = [x for x in data if np.abs((x - mean) / std) > threshold]
    return zscores, len(outliers)
```

#### 3.4. Z-Score 기법의 장점과 단점
##### 장점 👍

1. **간단하고 직관적**

> Z-Score는 평균과 표준편차를 이용한 간단한 계산으로 이루어져 있어, 구현하기 쉽고 결과 해석이 직관적입니다.

2. **표준화된 점수**

> 데이터 포인트가 데이터셋의 평균으로부터 얼마나 떨어져 있는지를 표준화된 형태로 표현하여, 서로 다른 데이터셋이나 변수 간 비교가 용이합니다.

3. **정규 분포 데이터에 적합**

> 데이터가 정규 분포를 따르는 경우, Z-Score는 이상치를 식별하는 데 매우 효과적입니다.

4. **확장성**

> 다양한 임계값 설정이 가능하며, 데이터의 특성에 맞게 조정할 수 있어 융통성이 뛰어납니다.

##### 단점 👎

1. **정규 분포 의존성**

> Z-Score 방법은 데이터가 정규 분포를 가정할 때 가장 잘 작동합니다. 데이터가 크게 비대칭적이거나 긴 꼬리를 가진 경우, 이상치 탐지에 오류가 발생할 수 있습니다.

2. **극단값에 민감**

> 극단적인 값이 포함된 경우, 이들 값이 평균과 표준편차에 큰 영향을 미칠 수 있으며, 이는 Z-Score 계산에 영향을 미칩니다.

3. **모든 이상치를 식별하지 못할 수 있음**

> Z-Score는 간단한 통계적 접근 방식이기 때문에, 모든 유형의 이상치를 완벽히 식별하지 못할 수 있습니다. 특히, 데이터셋에 이상치가 많은 경우 효과적이지 않을 수 있습니다.

4. **이진 결정의 어려움**

> 어떤 데이터 포인트를 이상치로 간주할지에 대한 명확한 기준이 없기 때문에, 임계값 설정이 주관적일 수 있으며, 이에 따라 결과가 달라질 수 있습니다.

Z-Score를 이용한 이상치 제거 방법은 이러한 장단점을 고려하여 신중히 적용해야 하며, 경우에 따라 다른 이상치 탐지 방법과 병행하여 사용하는 것이 좋습니다. 데이터의 특성과 분석 목적에 따라 적절한 방법을 선택하는 것이 중요합니다.

### 4.IQR(Interquartile Range)을 활용하여 이상치 발견해보기!

#### 4.1. IQR (Interquartile Range) 이란?
IQR(Interquartile Range)은 데이터 세트의 중간 50% 범위를 측정하는 통계적 방법으로,  
데이터의 중간값 주변의 변동성을 파악하는 데 유용합니다.  
구체적으로, IQR은 데이터 세트의 제1사분위수(Q1, 하위 25%)와 제3사분위수(Q3, 상위 25%) 사이의 차이로 정의됩니다.  
이는 데이터 세트의 중앙 부분에 대한 분산을 나타내며, 특히 이상치 탐지에 매우 유용합니다.

![](https://i.imgur.com/l5j43YV.png)


##### IQR의 계산 방법

IQR은 데이터셋의 1사분위수(Q1)와 3사분위수(Q3)를 계산함으로써 얻어집니다.  
Q1은 데이터셋의 하위 25%에 해당하는 값이고, Q3는 상위 25%에 해당하는 값입니다.  
따라서 IQR은 `Q3 - Q1`로 계산되며, 이는 데이터의 중간 범위에 대한 전반적인 퍼짐 정도를 나타냅니다.

##### 이상치의 경계 설정

이상치를 식별하기 위해 IQR을 사용하여 하한 경계와 상한 경계를 설정합니다.  
하한 경계는 `Q1 - 1.5 * IQR`로, 상한 경계는 `Q3 + 1.5 * IQR`로 계산됩니다.  
이러한 방식으로 설정된 경계를 벗어나는 데이터 포인트는 일반적인 범위를 벗어난 것으로 간주되어 이상치로 분류됩니다.

##### 이상치의 제거

데이터 포인트가 설정된 하한 경계보다 낮거나 상한 경계보다 높은 경우, 해당 데이터는 이상치로 간주되어 제거됩니다.  
이렇게 함으로써 데이터 분석이나 모델링 과정에서 이상치의 영향을 줄일 수 있습니다.

#### 4.2. IQR을 이용한 이상치 탐지 실습

이상치를 탐지하고 제거하기 위해 IQR 을 활용하는 두 가지 방법에 대해 설명해볼건데요!

1. **Quantile 함수를 활용하여 IQR 이상치 제거** : pandas 라이브러리의 `quantile` 함수를 사용하여 데이터 세트의 25번째 백분위수(Q1)와 75번째 백분위수(Q3)를 계산하고, 이를 통해 IQR을 구합니다. 이상치는 Q1에서 1.5 * IQR을 뺀 값보다 작거나, Q3에 1.5 * IQR을 더한 값보다 큰 데이터 포인트로 정의됩니다. 이상치로 간주된 데이터 포인트들은 분석에서 제외하거나 추가 조사를 통해 처리될 수 있습니다.
    
2. **Percentile 함수를 활용하여 IQR 이상치 제거**: NumPy 라이브러리의 `percentile` 함수를 사용하여 동일한 백분위수를 계산합니다. 이 함수는 전체 데이터 배열을 입력으로 받아, 지정된 백분위수에 해당하는 값을 반환합니다. 이후, quantile 함수와 유사하게 IQR을 구하고 이상치를 식별할 수 있습니다.

```python
def out_iqr(data):

num_lower_outliers = len(lower_outliers)
num_upper_outliers = len(upper_outliers)
```

##### 장점 👍

1. **극단치에 대한 강한 내성**

> IQR은 데이터 세트의 중앙 부분에 초점을 맞추므로 극단적인 값을 가진 이상치의 영향을 덜 받습니다. 이는 데이터가 비대칭적인 분포를 가질 때 특히 유용합니다.

2. **직관적 이해**

> IQR은 사분위수라는 기본적인 통계 개념에 기반하여, 데이터의 중간 범위를 쉽게 이해하고 해석할 수 있게 합니다.

3. **비모수적 접근**

> IQR 방법은 데이터가 특정 분포(예: 정규 분포)를 따르지 않는 경우에도 사용할 수 있습니다. 이는 데이터가 다양한 형태의 분포를 가질 수 있는 실제 상황에서 유용합니다.

##### 단점 👎

1. **정보 손실의 가능성**

> 이상치로 간주되는 데이터 포인트를 제거하면 중요한 정보를 잃을 수 있습니다. 특히, 이상치가 데이터에 대한 중요한 신호를 포함하고 있을 경우, 이러한 정보 손실은 분석 결과에 부정적인 영향을 미칠 수 있습니다.

2. **임의의 임계값 설정**

> 이상치를 정의하는 데 사용되는 임계값(예: 1.5 x IQR)은 어느 정도 임의적입니다. 이 임계값은 상황에 따라 조정되어야 할 수 있으며, 이에 대한 명확한 가이드라인이 없는 경우가 많습니다.

IQR 방법은 데이터의 중간 범위를 분석하여 이상치를 탐지하는 효과적인 방법으로, 특히 극단값이 포함된 데이터 세트에 적합합니다. 그러나 이상치를 어떻게 처리할지는 데이터의 성격과 분석 목적에 따라 신중하게 결정해야 합니다.

### 5.이상치를 꼭 제거해야 할 필요가 없습니다❗️

우리가 "이상치 탐지" 주제를 학습할 때, 이상치를 찾아서 제거하는 과정을 반복적으로 다루고 있습니다. 하지만 이상치를 반드시 제거해야 하는 것은 아닙니다. 이 질문은 데이터 과학과 통계 분야에서 자주 논의되는 주제 중 하나입니다. 이상치 제거는 일반적으로 사용되지만, 이상치를 다루는 다양한 다른 접근 방식도 있습니다.

1. **데이터 변환**: 이상치의 영향을 줄이기 위해 데이터를 변환할 수 있습니다. 데이터를 로그로 변환하거나, 제곱근을 취하거나, 역수를 취하는 등의 방법을 사용하여 데이터의 분포를 조절할 수 있습니다. 이렇게 하면 이상치의 영향을 줄일 수 있습니다.
    
2. **이상치 점수화**: 이상치를 제거하지 않고 데이터에서 이상치를 식별하고 점수화할 수 있습니다. 이 점수를 활용하여 모델링에 활용하거나, 이상치의 정도를 파악할 수 있습니다.
    
3. **이상치 치환**: 이상치를 다른 값으로 대체할 수 있습니다. 이상치를 해당 특성의 중앙값이나 평균값 등으로 대체하거나, 가장 가까운 정상치로 대체하는 방법을 사용할 수 있습니다.
    
4. **모델 기반 접근**: 일부 머신 러닝 모델은 이상치에 강건하며, 이상치를 자동으로 처리할 수 있습니다. 예를 들어, 랜덤 포레스트와 같은 트리 기반 모델은 이상치에 민감하지 않을 수 있습니다.
    
5. **이상치를 고려한 모델링**: 때로는 이상치가 중요한 정보를 제공하는 경우도 있습니다. 이런 경우, 이상치를 제거하지 않고 모델링을 수행하고, 결과에 미치는 영향을 조사하는 것이 유용할 수 있습니다.
    

마지막으로, 이상치 처리 방법은 데이터의 특성, 분석 목적, 사용 가능한 도구 등에 따라 다를 수 있습니다. 이상치는 때로는 중요한 신호일 수 있으며, 이러한 상황에서는 이상치를 제거하는 대신 다른 방법으로 다루는 것이 더 합리적일 수 있다는 점 유의해주세요.🤗

### 2.1. DBSCAN 이란?
DBSCAN은 데이터 포인트들을 기반으로 클러스터를 형성하고, 이 과정에서 클러스터에 속하지 않는 포인트들을 이상치로 간주하는 클러스터링 알고리즘입니다.  
K-Means 알고리즘의 대안으로 사용되며, 미리 클러스터의 수를 정할 필요 없이 데이터 자체의 밀도에 기반하여 클러스터링을 수행합니다.  
DBSCAN에서 고려하는 세 가지 주요 개념에 대해 간략히 설명드리겠습니다.

1. **핵심 포인트(Core Points)**
    
    - 핵심 포인트는 _"주변 지역(eps 거리 내)에 일정 수(min_samples) 이상의 이웃 포인트가 있는 데이터 포인트"_ 입니다.
    - 이 포인트들은 클러스터링 과정에서 클러스터의 '핵심'을 형성합니다.
2. **경계 포인트(Border Points)**
    
    - 경계 포인트는 _"핵심 포인트의 이웃이지만, 그 자체로는 핵심 포인트의 조건(즉, min_samples 이상의 이웃)을 충족하지 않는 포인트"_ 입니다.
    - 이들은 클러스터의 경계를 형성합니다.
3. **노이즈 포인트(Noise Points)**
    
    - 노이즈 포인트는 _"핵심 포인트나 경계 포인트가 아닌 모든 포인트"_ 로, 어떤 클러스터에도 속하지 않습니다.
    - 이 포인트들은 데이터셋에서 이상치를 나타냅니다.

#### DBSCAN 알고리즘의 작동 원리
DBSCAN의 원리를 이해하기 위해 예를 들어보겠습니다.  
아래 이미지에는 회색으로 표시된 일부 데이터 포인트가 있습니다.  
DBSCAN 이 이러한 데이터 포인트를 어떻게 클러스터링하는지 살펴보겠습니다.

![](https://i.imgur.com/DMq12El.png)


DBSCAN(밀도 기반 공간 클러스터링)은 데이터의 공간에서 각 데이터 포인트 주변에 epsilon(엡실론) 반경의 원을 형성하고, 이를 기반으로 데이터 포인트를 **핵심(Core) 포인트, 경계(Border) 포인트, 노이즈(Noise) 포인트** 로 분류합니다.

이 때 고려해야 하는 두 가지 주요 매개변수는 **epsilon(엡실론)** 과 **minPoints(최소 데이터 포인트 수)** 입니다.  
epsilon은 각 데이터 포인트 주변에 형성되는 원의 반경으로, 데이터 포인트 간의 밀도를 정의하며,  
minPoints는 해당 원 내부에 존재해야 하는 최소 데이터 포인트 수로, 해당 데이터 포인트를 핵심 포인트로 분류하기 위한 조건입니다.

![](https://i.imgur.com/0H1X70C.png)
  

위 그림은 minPoints가 4로 설정된 DBSCAN 알고리즘에 의해 형성된 클러스터를 보여줍니다.  
여기서 모든 데이터 포인트 주위에 동일한 반경의 epsilon(엡실론) 원이 그려져 있습니다.  
이 원 내에 4개 이상의 데이터 포인트를 포함하는 모든 포인트는 클러스터의 핵심 포인트로 간주되어 빨간색🔴으로 표시됩니다.  
원 내에 4개 미만의 포인트를 가지고 있으나, 핵심 포인트에 인접해 있는 포인트들은 경계 포인트로 분류되어 주황색🟠으로 표시됩니다.  
그리고 원 내에 4개 미만의 포인트를 가지고 있으면서 어떠한 핵심 포인트에도 속하지 않는 포인트들은 노이즈로 간주되어 연두색🟢으로 표시됩니다.

### 2.3. DBSCAN 를 활용한 이상치 탐지의 장점과 단점

DBSCAN (Density-Based Spatial Clustering of Applications with Noise)은 이상치 탐지에 자주 사용되는 밀도 기반의 클러스터링 알고리즘입니다. 이 알고리즘은 특히 클러스터의 크기나 모양이 불규칙하거나 밀도가 다를 때 유용합니다. 이상치 탐지에 DBSCAN을 사용하는 것의 장점과 단점은 다음과 같습니다.

#### 장점 👍

1. **모델 가정 불필요**

> DBSCAN은 클러스터의 형태에 대한 가정을 하지 않기 때문에, 원형이 아닌 클러스터를 잘 탐지할 수 있습니다.

2. **클러스터 개수 설정 불필요**

> 클러스터의 개수를 사전에 정할 필요가 없습니다. DBSCAN은 데이터로부터 클러스터의 개수를 자동으로 결정합니다.

3. **이상치에 강건함**

> DBSCAN은 밀도가 낮은 영역의 데이터 포인트를 자연스럽게 이상치로 분류합니다.

4. **노이즈와 클러스터 구분**

> 알고리즘이 이상치를 노이즈로 간주하여 데이터에서 자연스럽게 분리합니다.

5. **데이터의 밀도에 따른 유연성**

> `eps`와 `min_samples` 파라미터를 조정하여 다양한 밀도를 가진 데이터셋에 적용할 수 있습니다.

#### 단점 👎

1. **파라미터 설정**

> `eps`와 `min_samples` 같은 파라미터 설정이 결과에 큰 영향을 미치며, 최적의 값을 찾기 위해 여러 시도가 필요할 수 있습니다.

2. **변수 스케일의 민감성**

> DBSCAN은 변수의 스케일에 민감하기 때문에, 스케일링과 같은 사전 데이터 처리가 중요합니다.

3. **고차원 데이터의 어려움**

> '차원의 저주'로 인해, 고차원 데이터에서 성능이 저하될 수 있습니다.

4. **밀도 변화에 민감**

> 데이터셋 내에서 밀도가 크게 변할 경우, 한 가지 `eps` 값으로 모든 클러스터를 적절히 식별하기 어렵습니다.

5. **클러스터 크기의 다양성**

> 매우 다양한 밀도를 가진 클러스터가 존재하는 경우, 모든 클러스터를 동일하게 잘 식별하지 못할 수 있습니다.



## LOF (Local Outlier Factor)

### 3.1. LOF 란?

LOF는 주변 이웃과 비교하여 데이터 포인트가 얼마나 이상한지를 평가하는 알고리즘입니다.  

이 방법은 각 데이터 포인트의 '지역적 밀도'를 계산하고, 이를 해당 포인트의 이웃들의 밀도와 비교합니다.  

LOF 점수는 데이터 포인트가 얼마나 주변 이웃과 다른지를 나타내며, 이 점수가 높을수록 해당 포인트는 이상치일 가능성이 높습니다.

![](https://i.imgur.com/AP1xxre.png)


#### LOF 알고리즘의 작동 원리

- **이웃 개수 설정**: LOF 알고리즘을 시작하기 전에, 고려할 각 데이터 포인트의 이웃 수(n_neighbors)를 결정해야 합니다. 이웃의 수는 알고리즘이 얼마나 지역적으로 데이터를 보는지 결정합니다.
    
- **지역 밀도 계산**: 각 데이터 포인트의 지역 밀도를 계산합니다. 이것은 n_neighbors개의 가장 가까운 이웃까지의 거리를 기반으로 하며, 이웃들 사이의 평균 거리로 표현할 수 있습니다.
    
- **LOF 점수 계산**: 각 데이터 포인트의 LOF 점수를 계산합니다. 이 점수는 데이터 포인트의 지역 밀도를 그 이웃들의 밀도와 비교함으로써 결정됩니다. LOF 점수가 1에 가까우면 데이터 포인트는 이웃들과 비슷한 밀도를 가지고 있다고 볼 수 있습니다. 점수가 1보다 많이 높으면 데이터 포인트는 이웃보다 밀도가 낮은 영역에 위치해 있으며, 이는 이상치일 가능성이 높음을 의미합니다.
    
- **이상치 결정**: LOF 점수가 특정 임곗값 이상인 데이터 포인트를 이상치로 분류합니다. 이 임곗값은 일반적으로 경험적으로 결정되거나, 특정 비율의 데이터 포인트가 이상치로 분류되도록 설정할 수 있습니다.
    
- **이상치 제거**: 이상치로 판정된 데이터 포인트를 데이터 세트에서 제거합니다.
    

### 3.2. LOF를 이용한 이상치 탐지 실습

#### 3.2.1. LOF 를 이용한 공복 혈당과 중성 지방 데이터의 이상치 탐지

`Local Outlier Factor (LOF)` 알고리즘을 사용하여 데이터셋에서 이상치를 탐지하는 과정을 살펴보도록 하겠습니다.
- `values` 함수를 통해 numpy 배열로 변환합니다.
- `LocalOutlierFactor` 알고리즘을 데이터에 적용합니다.
```python
from sklearn.neighbors import LocalOutlierFactor

# 데이터 준비
LOF_train = X_train.copy()
numeric_columns = ['공복 혈당', '중성 지방']
data_numeric = LOF_train[numeric_columns].values  

# Local Outlier Factor 모델 생성
clf = LocalOutlierFactor(n_neighbors=50, contamination='auto')

# 이상치 탐지
labels = clf.fit_predict(data_numeric)
pd.Series(labels).value_counts()

 1    4781
-1     119
dtype: int64
```

#### 3.2.2.LOF를 활용한 이상치 제거 결과

`Local Outlier Factor (LOF)` 알고리즘을 사용한 이상치 탐지 결과를 바탕으로 이상치가 아닌 데이터 포인트들을 필터링하고, 그 수를 계산해보겠습니다.

- 이상치가 아닌 데이터 포인트들만을 필터링하기 위해 `LOF_train` 데이터프레임에서 `outliers_lof` 열의 값이 `-1`이 아닌 행들만을 선택합니다. 결과는 `sample_no_outliers`라는 새로운 데이터프레임에 저장됩니다.
```python
LOF_train['outliers_lof'] = labels

sample_no_outliers = LOF_train[LOF_train['outliers_lof'] != -1]

display(sample_no_outliers.head(3))
display(f"이상치가 아닌 데이터 포인트들의 수: {len(sample_no_outliers)}")
```

### 3.3.LOF 를 활용한 이상치 탐지의 장점과 단점

#### 장점 👍
1. **지역적 밀도 차이 기반**

> LOF는 각 데이터 포인트의 지역적 밀도를 고려하여 이상치를 탐지합니다. 이 방법은 데이터셋의 전반적인 밀도 분포와 상관없이, 지역적 관점에서 이상치를 정확하게 식별할 수 있게 해줍니다.

2. **다양한 데이터셋에 적용 가능**

> LOF는 다양한 형태와 밀도를 가진 데이터셋에 적용될 수 있으며, 특히 밀도가 불균일한 데이터셋에서 유용합니다.

3. **이상치의 순위화**

> LOF는 단순히 이상치를 식별하는 것이 아니라, 이상치로 판단되는 정도를 점수로 제공합니다. 이를 통해 이상치들 사이에서도 상대적인 이상도를 평가할 수 있습니다.

4. **파라미터 조정의 유연성**

> 사용자는 이웃의 수(`n_neighbors`)와 같은 파라미터를 조정하여 알고리즘의 민감도를 조절할 수 있습니다.

#### 단점 👎
1. **파라미터 선택의 어려움**

> 올바른 `n_neighbors` 값을 선택하는 것이 중요하며, 이 값에 따라 이상치 탐지 결과가 크게 달라질 수 있습니다. 적절한 값 설정은 종종 경험적인 접근이 필요합니다.

2. **고차원 데이터에 대한 한계**

> 고차원 데이터에서 거리 기반 알고리즘은 "차원의 저주"의 영향을 받을 수 있으며, 이는 LOF의 성능 저하로 이어질 수 있습니다.

3. **계산 복잡성**

> 특히 큰 데이터셋에서는 각 데이터 포인트의 이웃을 찾는 과정이 계산적으로 복잡할 수 있습니다.

4. **데이터 스케일에 민감**

> 서로 다른 스케일의 변수를 포함한 데이터셋에서 LOF를 사용하기 전에 적절한 스케일링이 필요할 수 있습니다.
