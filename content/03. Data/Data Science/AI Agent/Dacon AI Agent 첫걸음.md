이렇게 보면 **AI 에이전트는 단순한 챗봇과는 확실히 다르다**는 걸 느끼실 거예요. 
챗봇은 보통 질문에만 답하거나 정해진 대로 반응하지만, **에이전트는 훨씬 더 적극적이고 똑똑하게 움직인답니다.**
  

## Agent 특징
#### **2.1. 자율성(Autonomy)**

**자율성은 AI 에이전트가 "인간의 지속적인 감독이나 개입 없이도 스스로 판단하고 행동할 수 있는 능력"** 을 말해요.  
예를 들어, 여러분이 "다음 주 미팅 일정을 정리해줘"라고 요청하면, 에이전트는 여러분의 캘린더를 확인하고, 참석자들과 소통하고, 적절한 시간을 찾아 일정을 잡는 과정을 모두 스스로 처리할 수 있어요.

**자율성이 중요한 이유는 바로 효율성 때문**이에요. 사람이 모든 단계마다 개입해야 한다면, 그건 결국 업무를 자동화하는 의미가 없겠죠?  
자율적인 에이전트는 사람의 시간과 노력을 절약해주고, 더 복잡한 작업에 집중할 수 있게 도와줍니다.

또한 자율성은 에이전트가 학습하고 발전할 수 있는 기반이 되기도 해요. 스스로 결정을 내리고 그 결과를 관찰함으로써, 에이전트는 시간이 지남에 따라 더 나은 판단을 할 수 있게 됩니다. 인간이 경험을 통해 배우는 것처럼, AI 에이전트도 자율적인 활동을 통해 성장할 수 있는 거죠.


#### 2.2.능동성(Proactivity)

**능동성은 단순히 요청에 응답하는 것을 넘어서, "적극적으로 문제를 예측하고 해결책을 제안"하는 특성**이에요.  
일반적인 시스템은 명령을 받았을 때만 반응하지만, 능동적인 에이전트는 사용자에게 도움이 될 만한 행동을 먼저 제안합니다.

예를 들어, 여러분이 회의 일정을 잡으려고 할 때, 능동적인 에이전트는 "이 시간에 이미 다른 중요한 약속이 있습니다. 대신 오후 3시는 어떠세요?"라고 제안할 수 있어요. 또는 "내일 서울로 출장 가는데 준비해야 할 것 있을까?"라고 물으면, "내일 서울에 비가 예보되어 있으니 우산을 챙기시고, 출장지 근처 맛집 목록도 준비해 드릴까요?"라고 응답할 수 있죠.

**능동성은 사용자 경험을 크게 향상시켜요. 사용자가 모든 것을 일일이 요청하지 않아도 에이전트가 필요한 부분을 미리 생각해주니까요.** 이는 좋은 비서가 상사의 필요를 미리 예측하고 준비하는 것과 비슷하죠.

이러한 능동성은 시간이 지남에 따라 더욱 정교해질 수 있어요. 에이전트가 사용자의 선호도와 패턴을 학습하면서, 더 개인화된 제안을 할 수 있게 되니까요. 처음에는 일반적인 제안을 하다가, 점차 "지난번에 좋아하셨던 그 카페가 새 메뉴를 출시했네요. 확인해 보실래요?"와 같이 사용자 맞춤형 제안을 할 수 있게 되는 거죠.


#### 2.3.도구 활용 능력(Tool Use)

**도구 활용 능력은 AI 에이전트가 "외부 도구나 서비스를 활용해 자신의 기능을 확장할 수 있는 능력"** 을 말해요. 이는 단순히 대화만 하는 것이 아니라, 실제로 작업을 수행하기 위해 필요한 도구들을 사용할 수 있다는 뜻이죠.

예를 들어, 에이전트는 웹 검색 엔진을 통해 최신 정보를 찾거나, 이메일 API를 통해 메시지를 보내거나, 캘린더 서비스에 접근해 일정을 관리하거나, 심지어 온라인 쇼핑 플랫폼을 통해 주문을 대행할 수도 있어요. 이런 도구 활용 능력이 있기 때문에 에이전트는 단순한 대화를 넘어 실질적인 도움을 줄 수 있는 거예요.

**도구 활용 능력의 중요성은 실행력에 있어요. 아무리 똑똑한 AI라도 실제 세계와 상호작용할 수 있는 방법이 없다면, 그 유용성은 제한될 수밖에 없죠.** 도구를 활용함으로써 AI 에이전트는 가상 세계를 넘어 실제 세계에서도 영향력을 발휘할 수 있게 됩니다.

흥미로운 점은 **최신 AI 에이전트들이 점점 더 많은 도구를 사용할 수 있게 되면서, 그 활용 범위가 계속 확장되고 있다**는 거예요. 처음에는 단순한 검색이나 계산 도구를 사용하는 정도였다면, 이제는 코드 실행, 이미지 생성, 데이터 분석 등 전문적인 도구들까지 활용할 수 있게 되었죠.

**이 세 가지 특징들이 결합되면, AI 에이전트는 단순한 소프트웨어나 챗봇과는 완전히 다른 차원의 도우미가 됩니다.** 자율적으로 판단하고, 능동적으로 제안하며, 다양한 도구를 활용해 복잡한 작업을 수행할 수 있으니까요.

다음 스텝에서는 이런 AI 에이전트가 일반 챗봇과 어떻게 다른지, 그리고 어떤 종류의 에이전트들이 있는지 더 자세히 알아보겠습니다.

## LangGraph란
LangGraph는 LangChain 팀에서 개발한 오픈소스 프레임워크로, **다양한 생성형 AI 에이전트 시스템과 워크플로우를 설계하고, 배포하며, 관리**하는 일을 훨씬 쉽게 만들어줍니다.  
LangGraph의 가장 큰 특징은 바로 “**그래프 구조**” 를 사용한다는 점이에요.  
그래프란, 간단히 말하면 **여러 작업(노드)을 선(엣지)으로 연결해서 흐름을** 만드는 방식입니다.

### LangGraph vs LangChain
LangChain과 LangGraph는 AI 작업 흐름을 설계하는 방식에서 큰 차이가 있습니다. LangChain은 작업이 **입력 → 단계 1 → 단계 2 → 출력**과 같이 일직선으로 순서대로 진행되는 **‘단순 체인 구조’** 입니다. 복잡한 분기나 반복, 상태 복구 같은 상황을 다루기는 어렵습니다.

LangGraph는 작업들이 서로 연결되고, **필요할 때 되돌아가거나, 여러 방향으로 분기**할 수 있는 **“그래프 구조”** 입니다. 조건에 따라 다른 경로를 선택하거나, 결과에 따라 다시 이전 단계를 반복하는 것도 자연스럽게 설계가능

![](https://i.imgur.com/Cezp1BT.png)

### LangGraph 구조
#### Node
**노드(Node)”는 하나의 작업 단위**
예를 들어, 사용자의 질문 읽기, AI 모델에게 물어보기, 외부 API에서 데이터 가져오기  
이처럼 **각각 다른 역할을 하는 작업들**이 모두 **하나씩의 노드**

노드는 보통 Python 함수 로 만들어집니다.  
함수 안에서는 필요한 작업을 처리하고, 그 결과를 반환

```python
def get_user_input(state):
   user_input = input("사용자: ")
   return {"user_input": user_input}
```

LangGraph에는 특별한 두 가지 노드가 있어요.
- **START**: 그래프의 출발점입니다. 일반적으로 사용자의 입력을 받거나, 초기 정보를 준비할 때 쓰여요.
- **END**: 그래프의 끝을 의미합니다. 모든 처리가 끝났을 때 도달하는 지점이죠.

#### Edge
엣지는 LangGraph에서 **노드(Node)와 노드를 연결해주는 “작업의 흐름”** 을 의미합니다.  
쉽게 말하면, “이 일을 다 했으면 다음엔 저 일을 해주세요!” 처럼 작업 사이의 **순서와 방향을 정해주는 역할**을 하는 거예요.  
하나의 노드에서 다른 노드로 넘어갈 때, 그 이동 경로를 **엣지 (Edge)** 라고 합니다.

엣지에는 크게 두 가지 종류가 있어요.

**🔵 일반 엣지 (Normal Edge)**  
가장 기본적인 형태입니다. "이 일을 마쳤으면, 그냥 다음 걸로 넘어가세요!" 하는 식입니다.  
예) 사용자 질문 받았으면 → AI에게 물어보기

**🔵 조건부 엣지 (Conditional Edge)**  
상태(State)를 보고 어디로 갈지 판단하는 엣지예요. "조건이 맞으면 A로, 아니면 B로 가세요!" 같은 경우죠.  
예) 날씨 정보가 필요하다면 검색 도구로, 아니라면 바로 답변하기

병렬 처리도 가능해요!  
LangGraph에서는 하나의 노드에서 여러 개의 엣지를 동시에 보낼 수 있습니다.  
즉, 여러 작업을 동시에 병렬로 처리 할 수도 있다는 거예요!  
예를 들어, 웹 검색과 동시에 데이터베이스 조회를 하고 싶다면 두 엣지를 동시에 보내, 각각의 결과를 받아온 후 합쳐서 최종 답변 생성


### LangGraph 기능
#### 3.1. 다양한 제어 흐름 지원
LangGraph는 여러 가지 유형의 AI 시스템을 만들 수 있도록 모든 종류의 작업 흐름을 자유롭게 설계할 수 있게 도와줍니다.

- **단일 에이전트 시스템**: 하나의 AI가 모든 일을 처리하는 구조
- **다중 에이전트 협력 시스템**: 여러 AI가 서로 협업해서 문제를 해결

쉽게 말해, "AI가 어떻게 돌아갈지" 흐름을 자유롭게 설계할 수 있다는 뜻이에요!

#### 3.2.인간 검토 기능 (Human-in-the-Loop)
AI가 모든 걸 알아서 판단하게 맡기는 게 불안할 때도 있죠?  
특히 중요한 결정이나 민감한 정보를 다룰 땐, 사람의 개입이 필요할 수도 있어요.

LangGraph는 이런 상황을 위해, “AI가 결과를 만들면 잠시 멈추고, 사람에게 확인을 받는” 시스템을 만들 수 있게 해줘요.

- 필요할 때 워크플로우 일시정지 가능
- 사람이 직접 결과를 확인 후 승인/수정 가능
- 이후 다시 AI 작업 이어서 진행 가능

보다 안정적이고 신뢰성 있는 AI 애플리케이션을 만들 수 있게 도와주는 기능이에요!

#### 3.3 실시간 스트리밍 지원
LangGraph는 작업이 진행되는 동안 중간 결과를 계속해서 전달받을 수 있습니다.  
LLM이 답변을 생성하는 순간순간을 실시간으로 볼 수 있다는 뜻이죠!

예를 들어 웹사이트에서 사용자가 질문하면, LLM이 답변을 "하나, 둘, 셋..." 하는 것처럼 글자를 하나씩 만들어내며 전송됩니다.

사용자 입장에서는 AI가 생각하는 걸 실시간으로 보는 듯한 경험을 줄 수 있어서 UX(사용자 경험)가 크게 향상돼요.

#### 3.4.지속성(Persistence)과 메모리 관리
AI 애플리케이션이 장시간 돌아가는 경우도 많죠.  
혹은 갑자기 꺼졌다가 다시 시작해야 할 수도 있고요.

LangGraph는 현재 상태를 저장했다가 나중에 다시 불러올 수 있는 기능을 제공합니다.

- 장기간 대화 유지 가능
- 세션 중단 후 재개 가능
- 인간 검토나 장애 상황에도 데이터 손실 없이 이어서 작업 가능

특히 **장시간 채팅, 비동기 작업, 복잡한 프로세스**에 매우 유용한 기능이에요.

#### 3.5.LangChain 생태계와의 완벽한 통합
LangGraph는 이미 잘 알려진 **LangChain 프레임워크 기반**으로 만들어졌습니다.  
그래서 기존에 만든 LangChain 도구들은 그대로 사용할 수 있어요.

뿐만 아니라,

- LangSmith: 디버깅 및 모니터링 도구
- LangGraph Platform: 그래프 기반 애플리케이션 플랫폼

같은 다른 도구들과도 쉽게 연동됩니다.


### 4.AutoGen × CrewAI × LangGraph 비교

최근 AI 개발 환경이 빠르게 진화하면서 단일 챗봇을 넘어서 여러 AI 에이전트가 협업하는 구조가 각광받고 있습니다. 이 분야에서 자주 언급되는 대표적인 다중 에이전트 프레임워크로는 **AutoGen**, **CrewAI**, 그리고 **LangGraph**가 있죠. 각 툴은 강조하는 바와 설계 철학이 조금씩 다르기 때문에, 어떤 상황에서 어떤 도구를 선택해야 할지 살펴보겠습니다.

#### 4.1.AutoGen
Microsoft에서 개발한 AutoGen은 **‘대화 중심’의 다중 에이전트 협업**을 쉽고 빠르게 실험해보고 싶은 분들께 안성맞춤인 프레임워크입니다. AutoGen의 핵심은 **에이전트들 간의 메시지 기반 대화**입니다. 여러 종류의 대규모 언어 모델(LLM)을 자유롭게 연결해 사용할 수 있고, **각 에이전트가 토론하듯 의견을 주고받으면서 문제를 해결**해 나가죠. 코드 실행이나 API 호출 기능이 기본으로 내장되어 있어, 챗봇이나 간단한 자동화 시스템을 몇 줄의 설정만으로 바로 프로토타이핑할 수 있다는 장점이 있습니다.

다만, AutoGen은 ‘자유로운 대화’에 초점을 맞추다 보니 **복잡한 분기 처리나 장기간 상태 유지**를 요하는 워크플로우 제어 기능은 다소 약할 수 있습니다. 반복 작업이 길어지거나, 그래프 형태로 흐름을 시각화해 정밀하게 관리해야 하는 상황이라면 추가적인 설계나 별도의 상태 관리 코드가 필요하다는 점을 염두에 두어야 합니다.


#### 4.2.CrewAI
CrewAI는 **‘역할 기반 협업 팀’** 을 빠르게 구성하여 **한 가지 목표를 달성하고 싶을 때** 유용한 도구입니다. 기획자, 디자이너, 개발자처럼 **서로 다른 역할(Role)을 가진 에이전트**들을 모아 하나의 “크루(Crew)”로 묶고, **각자의 목표(Goal)와 도구(Tool), 성격(Personality) 등을 세부적으로 설정**할 수 있죠. 이를 통해 **“누가 어떤 일을 언제까지 어떻게 할지”** 가 명확해지고, 간단한 순차형 워크플로우를 직관적으로 설계할 수 있습니다.

그렇지만 **복잡한 분기나 병렬 처리, 장기간 실행되는 상태 저장 같은 고급 기능은 제한적**입니다. 워크플로우가 순서에 따라 깔끔하게 이어질 때 가장 빛을 발하며, 한두 단계 넘어가는 작업이라면 매우 빠른 속도로 팀 기반 에이전트를 구현해볼 수 있지만, 복잡도가 높아질수록 제약이 눈에 띕니다.


#### 4.3.LangGraph
LangGraph는 세 가지 중 가장 **‘정교한 흐름 제어’** 에 특화된 그래프 기반 프레임워크입니다. 마치 지하철 노선도를 그리듯, 작업 단위인 노드(Node)와 이들을 연결하는 엣지(Edge)를 통해 전체 워크플로우를 시각적으로 설계합니다. 상태(State)를 내부적으로 관리해 중간에 멈추더라도 저장된 지점부터 바로 **재개**할 수 있고, **분기·반복·병렬 처리 같은 복잡한 흐름**도 자유자재로 구현할 수 있죠. 게다가 **Human‑in‑the‑Loop**를 지원해 중간 검토나 수정이 필요한 단계에 사람이 개입하도록 만들 수도 있습니다.

이처럼 매우 강력한 제어 기능을 제공하는 대신, **처음 접하는 개발자에게는 개념 이해와 코드 작성이 다소 까다롭게** 느껴질 수 있습니다. 실험적인 프로토타입보다는 실제 서비스나 장기간 운영해야 하는 고도화된 시스템에 더 잘 어울리는 도구입니다.

#### 언제 어떤 프레임워크를 선택할까?

- **빠르게 대화형 에이전트를 실험하고 싶다면** → **AutoGen**
- **역할 기반 팀을 구성해 순차 협업을 해보고 싶다면** → **CrewAI**
- **복잡한 조건 분기, 상태 저장, 장기 운영 시스템이 필요하다면** → **LangGraph**

각 툴이 지향하는 방향과 강점이 분명히 다르니, “무엇을 만들 것인가?”, “얼마나 복잡한 흐름이 필요한가?”를 기준으로 선택해 보세요. 여러 프레임워크를 직접 써보며 자신에게 딱 맞는 툴을 찾는 것도 좋은 방법입니다!
