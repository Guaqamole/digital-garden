### 1. 식봄 검색 v2 ElasticSearch Cluster
모니터링 방법
- wcc prod grafana: https://grafana.marketboro.com/d/prodfssearchclusteroverview/elasticsearch-cluster-monitoring?orgId=1&refresh=5s

#### Grafana (ES가 잘 동작중인가?)
권한이 있으면 회사 구글 계정으로 들어간다. 없으면 Devops 팀에게 요청해야한다. 

볼 수 있는 지표:
- cpu 사용량
- JVM memory
- node healthcheck

#### Kibana (최신 색인으로 검색 유입이 되고있는가?)
남규 맥북에서 실행되고 있는 키바나 프로세스 (위 아이피로 접근 안되면 그냥 남규 맥북 비밀번호 치고 localhost:3306 접근)

볼 수 있는 지표:
- index 별 지표 (search-rate: index 별 검색 요청이 얼마나 되는지)
- node 별 사용량

#### **문제시 대응방법**
문제되는 ElasticSearch Node를 재시작 해본다.
> [!warning] ES1번 노드는 더욱 신중히
> 현재 색인 Endpoint는 ES1번 노드 172.31.134.184 로 되어있기 때문에,
> 만약 1번 노드가 DOWN 된다면 색인은 진행되지 않는다.

- es1: 172.31.134.184
- es2: 172.31.134.164
- es3: 172.31.140.102
```python
1. ssh로 prod-mgmt 접근 -> ssh ec2-user@3.35.28.97
2. 'es2' 입력후 es2번 노드 접근
3. sudo systemctl restart elasticsearch
```

#### **문제시 대응방법**
ECS 재시작 및 DB 부하 확인
AWS Console 접근 후 DB 성능 개선 도우미 접속
![|650](https://i.imgur.com/nmkYIrd.png)

필요한 경우, mgmt 서버에 구비해둔 v1-da , v1-dc 색인 jar 파일을 실행시켜 색인 진행.
```python
ssh prod-mgmt

ls /home/ec2-user/dc-fs-search-indexing
dc-fs-search-indexing-v1-da.jar  dc-fs-search-indexing-v1-dc.jar  nohup.out  options  run.sh
```

`dc-fs-search-indexing-v1-da.jar` 파일은 예전 DA-ES 에 색인을 하는 Spring Batch Application이다.
아래 명령어 수행 후 색인이 진행된다.
```python
nohup /opt/java/jdk11/bin/java -Dspring.profiles.active=prod -jar /home/ec2-user/dc-fs-search-indexing/dc-fs-search-indexing-v1-da.jar &

# tail 명령어로 수행 확인
tail -f nohup.out
```
